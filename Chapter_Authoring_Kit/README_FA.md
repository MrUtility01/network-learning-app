# بستهٔ همکاری برای تولید فصل‌های دانشنامه شبکه

این بسته قرارداد فایل‌ها و قالب آماده‌ای است که برای اضافه‌کردن فصل‌ها به برنامه استفاده می‌کنیم. هدف این است که هر بار فقط یک ZIP استاندارد از فصل بفرستی؛ برنامه با حفظ شناسه‌ها محتوا را اضافه کند و تکراری‌ها را دوباره ثبت نکند.

## فایل‌های داخل بسته

- `template_chapter/`: پوشهٔ آماده برای شروع نوشتن یک فصل؛ بانک‌های JSON عمداً خالی‌اند تا رکورد ساختگی وارد برنامه نشود.
- `authoring/RECORD_SCHEMAS_FA.md`: ساختار دقیق فیلدها و مثال رکوردها.
- `authoring/slug_map.json`: slugهای مورد استفاده برای نگاشت خودکار به ۲۹ فصل پایه.
- `SECURITY_AND_ETHICAL_HACKING_FA.md`: استاندارد اجباری برای محتوای هک قانونمند و آزمون مجاز.
- `scripts/validate_chapter_pack.py`: بررسی ساختار بسته پیش از Import.

## روال پیشنهادی همکاری

1. یک کپی از `template_chapter` بساز و نام آن را مثلاً `ch06_cisco_switching` بگذار.
2. `manifest.json` را از `authoring/slug_map.json` با عنوان/slug همان فصل پر کن.
3. متن کامل فصل را در `chapter_reference.md` تکمیل کن؛ هر درس خرد و مستقل را هم در `lessons.json` قرار بده.
4. سؤال، کارت، دستور، مثال و آزمایشگاه را در فایل JSON نوع خودش قرار بده.
5. عکس‌ها و نمودارهای مجاز را در `assets/` بگذار؛ فایل‌هایی را که در متن ارجاع می‌دهی همراه ZIP بفرست.
6. تا پیش از بازبینی نهایی، وضعیت‌ها `review_required` باشند.
7. اعتبارسنجی را اجرا و پوشهٔ فصل را ZIP کن.
8. ZIP را از بخش «واردکردن محتوا» وارد کن. ابتدا روی نسخهٔ پشتیبان/نمونه آزمایش کن.

## اندازه و عمق پیشنهادی

این‌ها هدف تحریری‌اند، نه الزام عددی برای همه فصل‌ها. فصل‌های بزرگ می‌توانند بیشتر داشته باشند:

- متن مرجع: هر فصل به اندازهٔ دامنهٔ واقعی‌اش، با تیترهای معنادار و جداول کامل.
- درس‌های کوچک: 10 تا 25 یا بیشتر، هر درس حول یک هدف یادگیری.
- سؤال‌ها: حداقل 100 سؤال برای فصل‌های عمیق، با کلید و پاسخ تشریحی بازبینی‌شده.
- فلش‌کارت: حداقل 150 کارت برای فصل‌های عمیق؛ بدون تکرار و با یک هدف در هر کارت.
- دستورات: متناسب با محصول/فصل؛ هر دستور همراه پلتفرم، نسخه، کاربرد، خروجی، احتیاط و بازگشت.
- آزمایشگاه‌ها: چند سطح از مقدماتی تا پیشرفته، با خروجی مورد انتظار، معیار قبولی، پاک‌سازی و خطایابی.
- سناریوهای عیب‌یابی: فرضیه‌ها، شواهد، دستورات خواندنی، شاخه‌های نتیجه، راه‌حل و rollback.

## نکتهٔ مهم

«بدون تکرار» به معنی حذف مثال مستقل، سؤال متفاوت، دستور مخصوص سازنده یا سناریوی ارزشمند نیست. مطالب تکراری توضیحی ادغام می‌شوند، اما موارد عملی متفاوت حفظ و به یک توضیح مرجع لینک می‌شوند. هر محتوای منبعی و تألیفی نیز باید از هم قابل تشخیص باشد.

## گردش‌کار نسخهٔ ۰.۴.۱ برنامه

- سطح‌های آموزشی مجاز: `beginner`، `intermediate`، `advanced` و `expert`.
- تمام محتواهای تازه یا واردشده باید ابتدا در وضعیت «در انتظار تأیید» بازبینی شوند؛ مقدار `source_status: verified` در فایل ورودی، تأیید داخل برنامه ایجاد نمی‌کند.
- پیش از Import بسته را اعتبارسنجی کن:

```bash
python scripts/validate_chapter_pack.py path/to/chapter-folder
# یا
python scripts/validate_chapter_pack.py path/to/chapter.zip
```

- در برنامهٔ نسخهٔ ۰.۴.۱، صفحهٔ «واردکردن محتوا» پیش‌نمایش بانک‌ها و فصل‌ها را نشان می‌دهد. پس از ورود، محتوا را در «مدیریت و تأیید محتوا» بازبینی کن و فقط موارد بررسی‌شده را تأیید کن.
- می‌توان بسته را مستقل نگه داشت یا آن را از صفحهٔ Import وارد برنامه کرد؛ شناسه‌های منبع را تا حد امکان در نسخه‌های بعدی ثابت نگه دار تا ورود تکراری و از دست‌رفتن پیوندها کاهش یابد.

## اندروید و PWA

همان قالب فصل (`template_chapter`) و اسکریپت `validate_chapter_pack.py` برای **ویندوز و اندروید** یکسان است. فرمت JSON و `manifest.json` تغییر نمی‌کند.

### جریان کار پیشنهادی
1. فصل را طبق همین راهنما بنویس و با `scripts/validate_chapter_pack.py` اعتبارسنجی کن.
2. پوشهٔ فصل را ZIP کن.
3. روی **ویندوز** برنامه را اجرا کن و از «واردکردن محتوا» ZIP را Import کن (همیشه با وضعیت بازبینی).
4. از صفحهٔ «مدیریت و تأیید محتوا» موارد را تأیید کن.
5. برای استفاده روی **اندروید**:
   - **PWA:** در Chrome اندروید به آدرس سرور محلی برو (`http://IP-رایانه:8000`) و «Add to Home screen» را بزن.
   - **APK:** پروژهٔ `android/` را در Android Studio باز کن، IP سرور را تنظیم کن و `assembleDebug` بساز.

### نکات مخصوص موبایل
- متن درس‌ها را کوتاه‌تر از حد لازم نکن؛ در UI موبایل اسکرول می‌شود. برای خوانایی، پاراگراف‌های متوسط و فهرست‌های مرحله‌ای بهترند.
- تصاویر را زیر ۲ مگابایت و ترجیحاً PNG/JPEG نگه دار؛ در `assets/` قرار بده و در Markdown با نام فایل ارجاع بده.
- آزمایشگاه‌ها و دستورات طولانی روی موبایل قابل مطالعه‌اند؛ برای اجرا همچنان به تجهیزات واقعی/آزمایشگاهی نیاز است.
- آزمون و فلش‌کارت روی PWA/WebView مثل دسکتاپ کار می‌کنند؛ کلید پاسخ فقط پس از ثبت پاسخ از سرور می‌آید.

### آنچه لازم نیست جداگانه برای اندروید ساخته شود
- فایل JSON جدا، slug جدا، یا بانک سؤال موبایل‌محور لازم نیست.
- یک بار Import روی سرور ویندوز کافی است؛ کلاینت اندروید همان API را می‌خواند.

جزئیات نصب اندروید: `android/README_FA.md` در ریشهٔ پروژه.
