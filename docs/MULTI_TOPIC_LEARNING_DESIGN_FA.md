# طراحی ارتقای چندموضوعی برنامه یادگیری

## قاعده پایه
این سند برای ارتقای برنامه موجود است، نه بازنویسی یا جایگزینی آن. نسخه رسمی ویندوز در مخزن فعلی طبق STATUS_WINDOWS_FIRST_FA.md برابر v0.4.3 در new/ است. بسته‌های قبلی، شناسه‌ها، ترتیب، وضعیت تأیید، پیشرفت، یادداشت‌ها و داده‌های کاربر باید حفظ شوند. هیچ مهاجرتی نباید بدون پشتیبان‌گیری و گزارش تغییرات، داده‌ای را حذف یا بازنویسی کند.

## مدل دامنه
Topic -> Chapter -> Section/ContentItem. قابلیت‌ها بر اساس topic.features فعال یا غیرفعال می‌شوند؛ غیرفعال بودن یک قابلیت نباید داده‌های موجود آن نوع را حذف کند. قابلیت‌ها شامل درس، نکته، سؤال، مثال، دستور، آزمایشگاه، تصویر، منبع، فلش‌کارت، مرور، برنامه‌ریز، آزمون و پیوست هستند.

## سازنده موضوع
فرم ساخت/ویرایش موضوع باید همهٔ موارد زیر را پشتیبانی کند:
- عنوان، شناسه پایدار، توضیح، نمایه محتوا، آیکون/رنگ، زبان، برچسب‌ها
- قابلیت‌های فعال
- فصل‌های انتخابی/افزودنی و ترتیب آن‌ها
- تعداد هدف درس، نکته، سؤال، مثال، دستور، تمرین آزمایشگاهی، تصویر و منبع برای هر فصل
- سطح مخاطب، پیش‌نیازها، عمق توضیح، سبک نگارش، قالب پاسخ، زبان و قواعد ارجاع
- تنظیمات مرور و برنامه‌ریزی
- تنظیمات تولید JSON و نسخه قالب
- پیش‌نمایش، اعتبارسنجی، ذخیره پیش‌نویس، ویرایش و تولید دوباره prompt

## تولید پرامپت
پرامپت باید از فرم موضوع و فصل‌ها ساخته شود و شامل قرارداد خروجی روشن باشد:
1. فقط JSON معتبر مطابق schema نسخه‌دار تولید شود؛ بدون Markdown fence یا متن بیرون JSON.
2. شناسه‌های پایدار و یکتا، شماره فصل و ترتیب صریح باشند.
3. تعداد درخواستی هر نوع محتوا رعایت شود؛ اگر قابلیتی خاموش است، آن آرایه خالی باشد.
4. محتوا مناسب پروفایل موضوع باشد؛ دستور و آزمایشگاه فقط در صورت فعال بودن تولید شوند.
5. تصاویر با شرح، متن جایگزین و منبع/مجوز یا مسیر فایل مشخص شوند؛ مدل نباید وانمود کند فایل تصویر واقعی پیوست کرده است.
6. برای منابع کتابی، نویسنده، عنوان، جلد، صفحه و چاپ در صورت در دسترس بودن ثبت شود؛ ارجاع ساختگی ممنوع و منبع نامطمئن با وضعیت نیازمند بررسی علامت‌گذاری شود.
7. پرسش‌ها پاسخ و توضیح داشته باشند؛ تستی‌ها گزینه‌ها و پاسخ صحیح معتبر داشته باشند.
8. محتوا ابتدا draft/pending است؛ تأیید با ابزار مدیریت انجام می‌شود.
9. قبل از import، JSON schema، تعدادها، ارجاعات داخلی، شناسه تکراری و فایل‌های پیوست اعتبارسنجی شوند.
10. prompt نهایی قابل مشاهده، ویرایش، کپی، ذخیره و نسخه‌بندی باشد.

## ورود، خروجی و پشتیبان‌گیری
- واردکردن پیش‌نمایش‌دار با حالت‌های: افزودن، ادغام، به‌روزرسانی انتخابی؛ هرگز جایگزینی/حذف خاموش.
- تشخیص بسته تکراری با pack.id + revision و هش محتوا؛ نمایش تعارض‌ها پیش از اعمال.
- خروجی موضوع/فصل/درس یا کل مجموعه به ZIP نسخه‌دار شامل manifest.json، content.json و assets/.
- پشتیبان‌گیری از داده، تنظیمات و وضعیت یادگیری؛ ذخیره خارج از مسیر دیتابیس و بررسی امکان بازیابی.
- نگهداری IDهای موجود و نگاشت IDهای قدیمی؛ گزارش import/export قابل ذخیره.

## پایگاه داده
پیش‌فرض باید با وضعیت واقعی نسخه موجود سازگار بماند. MySQL به‌عنوان گزینهٔ پیش‌فرض هدف کاربر ثبت شود، اما تغییر provider فقط پس از بررسی معماری فعلی مجاز است. پشتیبانی از SQLite/PostgreSQL/SQL Server باید از طریق لایه دسترسی داده و migrations انجام شود؛ نام دیتابیس را صرفاً در UI عوض نکنیم. قبل از تغییر provider، تست اتصال، مهاجرت schema، transaction، encoding فارسی، backup/restore و سازگاری همه queryها لازم است. اگر نسخه موجود در حال حاضر MySQL نیست، نصب ارتقایی نباید خودکار دیتابیس را تبدیل کند؛ انتخاب صریح و wizard انتقال داده لازم است.

## امنیت و تنظیمات پیشرفته
- تنظیمات شبکه: host/bind address، پورت (پیش‌فرض سازگار با نسخه فعلی؛ پورت 82 در پیکربندی کاربر مطرح شده)، تست اشغال بودن پورت، health check و نمایش خطا.
- کلیدها/گذرواژه‌ها نباید در خروجی JSON، prompt، log یا backup رمزنگاری‌نشده درج شوند.
- رمزگذاری گذرواژه با الگوریتم مناسب، نشست امن، محدودیت تلاش ورود، CSRF/CORS درست، اعتبارسنجی ورودی، حداقل سطح دسترسی، ثبت رویدادهای مدیریتی.
- تنظیمات backup، مسیر داده، retention، log level، export diagnostics و وضعیت سرویس.
- تغییرات حساس نیازمند تأیید، ثبت تاریخچه و امکان بازگشت هستند.

## مرور و برنامه‌ریز
- مرور مبتنی بر یادآوری فعال و تکرار فاصله‌دار.
- تنظیم هدف روزانه بر حسب تعداد آیتم و دقیقه، روزهای فعال، زمان اعلان و سهم هر موضوع.
- پاسخ هر آیتم: دوباره، سخت، خوب، آسان؛ زمان بعدی مرور با توجه به عملکرد تعیین شود.
- داشبورد: مطالب سررسید، عقب‌افتاده، دقت پاسخ، زمان مطالعه، روند هفتگی، موضوعات ضعیف و تکمیل فصل.
- خاموش کردن مرور برای یک موضوع نباید تاریخچه مرور آن را حذف کند.

## آزمون‌های پذیرش و محافظت از داده
- fixture و snapshot از نسخه قدیمی پیش از مهاجرت؛ شمارش فصل‌ها، محتوا، شناسه‌ها، پیشرفت و approval status قبل/بعد.
- تست import هر ZIP قدیمی شناخته‌شده، بسته تکراری، بسته ناقص، JSON نامعتبر و conflict.
- تست add/edit/delete با soft-delete یا تأیید صریح و امکان undo؛ حذف parent نباید بی‌هشدار childها را حذف کند.
- تست پورت اشغال، قطع دیتابیس، پشتیبان و بازیابی، و متن فارسی/RTL.
- تست رگرسیون برای همهٔ قابلیت‌های فعلی؛ خروجی نهایی فقط پس از تست واقعی و گزارش صادقانه قابل انتشار است.
